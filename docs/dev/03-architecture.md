## 模块划分

### mqtt_codec (协议层) — 已完成

- v4 模块: MQTT v3.1.1 协议支持
- v5 模块: MQTT v5.0 协议支持

### heron_core / heron_mqtt / heron_storage — 已实现

- TCP 与 WebSocket 监听，按 CONNECT 选择 v3.1.1 或 v5.0 编解码
- 会话、主题树、订阅与 QoS 0/1/2 路由
- `Storage` 接口：默认内存实现，PostgreSQL 由 SeaORM 写入

### heron_auth (认证授权) — 已实现

- Authenticator: 用户名/密码、Token、客户端证书身份
- Authorizer: 优先级 ACL
- 静态钩子 `BrokerHooks` 已挂接连接、订阅与发布流程

### heron_rules (规则引擎) — 已实现

- Rule Parser: 规则解析器 (SQL 形式与 `all`/`any` 条件)
- Rule Engine: 规则执行引擎，通过 `BrokerHooks` 接入 Broker 生命周期
- Actions: `log`、`drop`、`reject`、`republish`、`transform`、`webhook`
- Hooks: `Hook` trait 钩子插件，在内置规则之前运行
- 规则经 `Storage` 持久化，重启后恢复

### heron_api (REST API) — 已实现

- Routes: `/api/v1` 客户端、主题、订阅、系统状态
- Health: `/health` 与 `/api/v1/system/health`
- Metrics: Prometheus 文本 `GET /metrics`

### heron_cluster (集群模块) — 计划中

- Raft: 共识协议实现
- gRPC: 节点间通信 (Tonic)
- Sync: 状态同步

### web (Web GUI) — 已实现

- React + Zustand + TanStack Router + shadcn/ui
- 通过 `GET /api/v1/events` 接收每秒快照和连接变化

## 数据流

### 消息发布流程

```
Client A (Publisher)
       │
       │ PUBLISH
       ▼
┌──────────────────┐
│  MQTT Broker     │
│  ┌────────────┐  │
│  │ Decoder    │  │ ── 解析 MQTT 数据包
│  └─────┬──────┘  │
│        ▼         │
│  ┌────────────┐  │
│  │ Auth/ACL   │  │ ── 权限检查
│  └─────┬──────┘  │
│        ▼         │
│  ┌────────────┐  │
│  │ Rules      │  │ ── 规则处理
│  └─────┬──────┘  │
│        ▼         │
│  ┌────────────┐  │
│  │ Router     │  │ ── 查找订阅者
│  └─────┬──────┘  │
│        ▼         │
│  ┌────────────┐  │
│  │ Storage    │  │ ── 持久化（可选）
│  └─────┬──────┘  │
│        ▼         │
│  ┌────────────┐  │
│  │ Encoder    │  │ ── 编码 MQTT 数据包
│  └─────┬──────┘  │
└────────┼─────────┘
         │ PUBLISH
         ▼
  Client B, C... (Subscribers)
```

### QoS 保证

| QoS | 描述 | 流程 |
|-----|------|------|
| 0 | 最多一次 | 直接发送，不确认 |
| 1 | 至少一次 | PUBLISH → PUBACK |
| 2 | 恰好一次 | PUBLISH → PUBREC → PUBREL → PUBCOMP |
